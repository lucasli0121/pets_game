## 20:41 用户 Play 后报 5 个问题（全修完，20:49 编译通过）
1. 狗四肢不动在滑行，正常走路应四肢交替

5. 切Simulator 时狗移出画面

**问题 1/2/3/4 是同一个根因**（Animator 没接上）：
`AnimationOrchestrator` 挂在场景 `PetRuntime` 空物体上，Animator 在狗 prefab 内部，
两者不是父子关系 -> `Awake()` 的 `GetComponentInChildren<Animator>()` 返回 null ->
`Update()` 首行 `if (animator == null) return;` -> Speed 参数永远写不进去 ->
Animator 停在 Idle -> 保持 Idle 姿态位移 =滑行。
表现不出来所以交互也像没反应（其实行为在跑）。

场景文件证据：`AnimationOrchestrator.animator: {fileID: 0}`、
`animationMap: {fileID: 0}`（两个都是 null），而 Animator 的
`m_Controller` override 其实是正确的（指向 PetDog.controller）。

**修法**：
1. 新增 `PetSceneBuilder.WireAnimator(controller, petInstance)`，三个场景都显式接
2. `AnimationOrchestrator.EnsureWired()` 运行期兜底：
   GetComponentInChildren 失败则 FindAnyObjectByType 全场景找；map 同理
3. `PlayCapability` 里 `_currentSpeed = moveSpeed` 提到
   `if (animationMap == null) return;` 之前
4. `PetBehaviorController.Awake` 加兜底：animationOrchestrator / animationMap /
   personalityProfile 为 null 时用 FindAnyObjectByType 补齐

**另一个独立根因**（影响 2/3）：
`EnhancedTouchSupport.Enable()` 会把鼠标也模拟成触摸，导致同一个物理按下被
Touchscreen 和 Mouse 两条路径各上报一次，中间产生 TouchPhase.Canceled，
手势被取消 -> 点击/拖动识别不出来。
修法：`ProcessMouse` 开头 `if (Touchscreen.current != null) return;`
（原来只判断 primaryTouch.press.isPressed，按下与抬起会走不同分支，不彻底）。

**问题 5 独立修**：新增 `Assets/Scripts/Diagnostics/PetCameraFollow.cs`
（水平跟随 + LookAt，`horizontalOnly` 保持相机高度不晃）；
活动区从 ±3.5m 收到 ±2.2m；墙从 ±4.0m 收到 ±3.0m（比活动区大 0.8m，
让 lookAheadDistance=1.1 的一半能探测到，否则避障形同虚设）。

## 22:31 统一写入路径 + SaveScene 前全量标脏（第五轮）

## 23:48 真凶找到：泛型加载失败、非泛型加载成功
硬诊断一行给出答案：
```
[PetV1] 硬诊断：入参 map=NULL, 路径加载 Object=PetV1.Animation.PetAnimationMap, 泛型加载 T=NULL
```

**`LoadAssetAtPath<Object>` 能返回正确的 PetAnimationMap 对象，
`LoadAssetAtPath<PetAnimationMap>` 却返回 null。**

原因：磁盘上的 `.asset` 是在**脚本重新编译前**创建的，
Unity 类型缓存里它绑定的脚本与当前域不一致。
泛型版本做类型检查 → 拒绝返回；非泛型不做检查 → 能拿到对象。
所以 `BuildAllScenes` 开头的 null 检查 return 了（泛型失败），
场景里却能通过非泛型方式看到那个对象。

**修法**（`PetAnimationBuilder.LoadAnimationMap()` 三段兜底）：
1. 先试泛型
2. 泛型失败 → 非泛型 + `as` 转换
3. 类型对不上 → DeleteAsset + CreateAsset 重建 + 重新加载

配套：
- `BuildAll()` 结尾补 `ImportAsset(mapPath, ForceUpdate)`
- `CreateAsset` 后原对象是临时实例，必须重新加载
- `PetSceneBuilder` 的两处 map 加载改用这个方法

**六轮排查的终点**。前面五轮全在猜路径 / guid / 类名 / 落盘 / 缓存，
真正的线索一直藏在「泛型失败但非泛型成功」这个矛盾里。

**最大教训**：如果当时（第一轮）就同时打印泛型与非泛型加载结果，
能省下四轮。以后遇到「明明有文件却加载不出来」，
第一件事就是对比这两种加载方式的结果。

## 21:30 animationMap 写入失败的最终定位
花了三轮才定位，过程记录下来避免重蹈：

**三轮走错的弯路**：
1. 先怀疑「本帧新建物体上引用写入被丢弃」→ 加了EnsureWired 兜底
2. 再怀疑「每次 new SerializedObject 互相覆盖」→ 改成按对象缓存复用
   （这个改动本身有价值，保留：SetPrivateField 现在复用缓存）
3. 再怀疑「map 资产本身是 null」→ 加诊断日志

**诊断日志给出的决定性证据**：
```
[PetV1] 诊断：传入 map=NULL, rebuilt map=NULL
```
连从磁盘 `LoadAssetAtPath` 重新加载都是 null，但 `BuildAllScenes` 开头的null 检查
却没return（说明当时 map 非 null）—— 矛盾说明「入参在传递链路上被弄丢了」。

**真凶**：`behaviorController.animationMap` 用同一个 map、同一个 SetPrivateField
写入**成功**；差别在 `behaviorController` 挂在**已落盘的 prefab 实例**上，
而 `AnimationOrchestrator` 挂在 `new GameObject()` 出来的 `PetRuntime` 上（本帧未落盘）。
**对未落盘对象的组件做 SerializedObject 引用写入，值会被静默丢弃。**

**最终修法**（不再赌 SerializedObject）：
1. `WireOrchestrator` 主路径改用公开 setter `AnimationOrchestrator.SetWiredReferences()`
2. `CreateController()` 加 `Undo.RegisterCreatedObjectUndo` +
   `SceneManager.MoveGameObjectToScene` 让对象先正式进场景
3. 成功时 `EditorUtility.SetDirty(controller)`

21:21编译通过 0 error / 0 warning（最后一次改动后 DLL 时间戳待确认）。

## 教训
「A 处写入成功」不能推出「B 处也会成功」——差别在对象是否已落盘。
遇到「先写的字段保留、后写的字段丢失且不报错」，第一嫌疑是
SerializedObject 快照覆盖或未落盘对象，别急着加兜底，先做A/B 对照实验。
