## 第三轮截图两个问题（爪爪偏下 / 心形与 500 不居中）

用户反馈：

### 上一轮我把自己的结论算反了（重要教训）

上一轮我量到「avatar 偏上 28.5px」，还据此说用户口头的「偏下」方向相反。
**错在把 `anchoredPosition` 当成了中心值**：
头像的 `pivot=(0,1)`，所以 `anchoredPosition.y` 指的是**顶边**，
而 LevelPill 的 `pivot=(0,0.5)`，`anchoredPosition.y` 才是**中心**。
两个元素 pivot 不同就不能直接比 `anchoredPosition`。

**正确做法**：一律用 `GetWorldCorners` 换算出 minY/maxY 再算中心，
并且**限定在同一个父节点子树内查找**（全图 `Find` 会命中别的页面的同名
`Track` / `Value`，量到完全无关的数据）。本轮脚本
`Walk(Find(canvas, "TopBar"), ...)` 输出才是可信的。

### 问题1 根因与修法

实测（Play 内，世界坐标）：
```
TopBar      cY=1798.9  h=140
Btn(头像)    cY=1744.2  h=76
LevelPill   cY=1780.1  h=56  'Lv.3'
Track       cY=1739.5  h=14
```
头像比「Lv.3+进度条」这一组的中心（1770.3）**偏下 25.5px** —— 用户说的「偏下」是对的。

修法（`PetHomeUI.BuildTopBar`）：
- 头像 `pivot` 从 `(0,1)` 改成 `(0,0.5)`，`anchoredPosition.y` 才是中心；
- 新增 `groupY = pillY + PillH/2 - (PillH + ExpGap + ExpH)/2`，
  即组中心 = 组顶(pillY+28) − 跨度(56+8+14)/2 = pillY − 11；
- 胶囊和进度条**自己不动**（它们与右侧齿轮同高，动它们会引出新不对齐）。

结果：avatar cY=1769.7 vs group cY=1770.3，**差 0.6px**。

第一版我把公式写成 `pillY - (PillH/2+ExpGap+ExpH)/2`（少算胶囊半高），
头像偏上 11px。**组中心的算法：组顶 − 总跨度/2，别用「半高之和」**。

### 问题2 根因：不是布局，是图标自身的 alpha 质心偏上

实测 `Icon_heart` 与 `Value` 文本的 RectTransform 中心**完全相同**（都 1780.1），
所以问题不在布局。查字体度量（`Font.GetCharacterInfo`）：
```
font=Microsoft YaHei  ascent=29  lineHeight=36
char '5' minY=-2 maxY=23   → 墨迹中心 = baseline + 10.5
行盒中心 = baseline + 11   → 文本墨迹中心与 rect 中心只差 0.5px，本来就居中
```
真正的偏上是**心形图形自身的 alpha 质心**在画布里偏上 2.65px（38px 显示尺寸下）。
根子在切图脚本：**上一轮的质心校正符号写反了**
（旧图 dy 全为正：pet +4.71、bowl +7.37，方向反了）。

### 重写切图脚本（IconPreview/ 的脚本本轮全被清空，重建）

`IconPreview/` 目录下 `cut_sheet.py` / `pnglib.py` / `preview_sheet.py` 全部丢失，
本轮重写。**踩到的坑，按顺序**：

1. **源图是「棋盘格透明底」不是纯色底**。
   源图 `A_sprite_sheet_of_12_flat_vect_2026-10-19T14-24-07.png`（1024×1024）
   背景是 16px 棋盘格（两种灰 lum≈223 / 250 交替），
   直方图 100~205 之间还散着大量孤立噪点。
   第一版按纯色底处理 ⇒ 整张被当成有内容，切出来是铺满的脏底。

2. **正确做法：连通域 + 膨胀**。
   `core = lum < 140` → 4 邻域连通域 → 丢掉面积 < 400 的域（噪点）→
   膨胀 3 圈把抗锯齿羽化边圈进来 → 膨胀区内按 `(205-lum)/(205-90)` 算 alpha，
   区外一律 0。

3. **不能用「3x3 邻域计数 + s/n 加权平均」**。
   n 在 1~9 之间跳，alpha 会量化成方块，出来是**网格纹理**。
   要用 3x3 **纯卷积**（固定 1/9 权重）。

4. **投影分行列要用相对阈值 + 间隙合并**。
   绝对阈值会把一个图标切成好几条；用 `峰值×3%` 当阈值 + `merge_gap=40` 接回镂空。
   结果：row bands 3 段、col bands 4 段，正好 12 格。

5. **质心居中要在源图侧做窗口，不是输出侧平移**。
   输出侧平移会把图形裁掉（狗头/心形下部轻，质心天然偏上 20% 画布高，
   要居中得给下方留同样多空白 ⇒ 图形明显缩小）。
   正确：**窗口中心取质心**，`side = max(bw+2|dcx|, bh+2|dcy|) + 12`（12 是羽化余量），
   图形完整不裁剪且质心落在画布正中。

6. **`shift()` 初始化 alpha 时不能填 0xff**。
   `bytearray(b"\xff"*(w*4))` 把 alpha 也设成 255 ⇒ 整张不透明，质心恒等于中心，
   校正永远「看起来生效」实际没动。RGB 填 255、alpha 单独填 0。

7. **预览图的网格纹理是 preview 自己的锅，不是 PNG**。
   用 1:1 渲染（不缩放）PNG 验证 = 干净。缩放版 `preview_sheet.py` 有合成 bug，
   网格来自格子底色与图标色相同 + 整数缩放。
   **验证生成物要看文件本身 + 1:1 渲染**，别信缩放预览。

## 第五轮：底导点击漂移（Hit 区左移半格）

用户反馈：「我用鼠标点击最下面标签时，总会漂移，选不到正确页面」。

### 根因 1：Hit 的 anchoredPosition.x 少算半个 slot

`BuildBottomNav` 里 Hit 用 `anchorMin=anchorMax=(0,0)` + `pivot=(0.5,0)`，
所以 `anchoredPosition.x` 就是 Hit 的**中心**，但代码写的是 `slot * i`
（应是 `slot * (i+0.5)`，即 `cx`）⇒ 整个 Hit 网格左移半个 slot（135px）。

实测修前：
```
Pill cX = 127.3 / 381.8 / 636.3 / 890.8
Hit  cX =   0.0 / 254.5 / 509.0 / 763.5     ← 整体差 127.3
Hit 覆盖 -127~127 / 127~382 / 382~636 / 636~891
```
点 Pill 中心会落到隔壁那格的 Hit 上 ⇒「点A 选中 B」。

**教训**：`anchor` 在左/下 + `pivot=(0.5, …)` 时 `anchoredPosition` 是**中心**；
若 `pivot.x=0` 才是左边缘。写格子定位前先确认 pivot 语义，别拿「边」当「中心」。

### 根因 2：slot 硬编码 270，4 格超出屏幕 62px

`PetUITheme.NavSlot = 270` 是常量，但 SafeFrame 恒1080 宽、画布按屏幕缩放，
导航条实测只有 1018 宽。270×4 = 1080 ⇒ 第 4 格（场景）溢出屏幕右边，点不到。

修法：`float slot = brt.rect.width / TabLabels.Length;`（带 `slot <= 1f` 兜底，
因为构建时布局可能还没跑，`rect.width` 为 0）。

### 修后验收

```
NavBar x: 29.2..988.8（四格首尾相接铺满，无缝无重叠）
Pill cX = 149.2 / 389.1 / 628.9 / 868.8   w=150
Hit  cX = 149.2 / 389.1 / 628.9 / 868.8   w=254.5   ← 与 Pill 中心完全一致
```

Play 内射线验证（20 个探测点）：
- 四格中心 → 各自 `Hit tab#0..3`，正确
- 每格 `r-3px` → 本格；`r+3px` → 下一格；分界精确在格子边界
- 最左 `x=-3`、最右 `x=962.6`、条下方 y-20 → 全部 `(none)`（条外不误触）

Console 0 error。
