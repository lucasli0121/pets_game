## Unity MCP 接入 —— 排查方式彻底改变

用户创建了 Unity MCP 连接器。立刻用它做了一件之前八轮都做不到的事：
**直接读运行时字段，而不是猜 YAML 文件**。

之前的问题在于我在 `Logs/Editor.log` 和场景文件里反复推断，
每次都要用户点窗口触发重编译。现在可以直接：
- `Unity_RunCommand` 读任意运行时字段、改场景、调构建菜单
- `Unity_GetConsoleLogs` 读 Console
- `Unity_SceneView_CaptureMultiAngleSceneView` 四视角截图

### MCP 的约束（踩过才知道）
- 类名必须 `internal class CommandScript : IRunCommand`
- **禁止反射**（`System.Reflection.BindingFlags.*` 直接被拦，报 unauthorized namespaces）
- **禁止 `GetInstanceID()`** —— Unity 6 已废弃，CS0619 编译失败
- `result.Log` 不支持 `{0:F3}` 格式化，会当字面量输出
- 改完 C# 调 `CompilationPipeline.RequestScriptCompilation()`，
  Unity 会中断 MCP（报 "Unity not detected"），等约 50 秒恢复
- 编辑器里 `Update`/`LateUpdate` 不跑，`QueuePlayerLoopUpdate()` 也不立即生效
- `cam.Render()` 离屏渲染在 URP 下出全白，截图要用 SceneView 工具

## 用 MCP 查出并修好的三个问题

### 1. PetDebugPanel.touchInputManager 为空 → 按钮静默失效
性能场景里我原来传的是 `null`（本意是不测触摸）。
但按钮代码是 `if (GUILayout.Button(...) && touchInputManager != null)`，
引用为空时不报错也不响应 —— 这就是用户看到的「点了没反应」。

修法：性能场景也建 TouchInputManager，三个场景统一。

### 2. TouchInputManager.targetCamera 为空
有 `Camera.main` 兜底所以功能正常，但显式写入更可靠。

### 3. BuildPerformanceScene 根本没调 WireBehavior
它手写了一套接线，**漏了 `personalityProfile`**。
所以性能场景的宠物没有性格配置（Awake 会自己造默认 BorderCollie）。
修法：改成统一调 `WireBehavior`，消除这类漏项。

顺带把 `WireBehavior` 里的
`AssetDatabase.LoadAssetAtPath<T>` 换成 `PetAnimationBuilder.LoadAnimationMap()` /
新增的 `LoadPersonalityProfile()`（三段兜底：泛型 → 非泛型 + as → 必要时重建）。

### 4. Floor 尺寸比围墙大 5 倍
Plane 原生 10m × scale 3 = 30m，而围墙只有 6m。
改成 scale 0.8（8m），覆盖活动区并留边缘。

## 主场景「狗与绿植重合」的真因（不是构图问题，是坐标 bug）

之前两轮都在改绿植的x/z 位置并加遮挡自检，都判���「自检通过」，
但用户截图里狗身上一直压着绿植。真因是坐标语义不一致：

`PetHomeSceneBuilder` 的 `Box` / `Sphere` / `Cylinder` 三个辅助函数写的是
```csharp
go.transform.SetParent(parent, true);   // 保世界
go.transform.position = pos;             // pos 被当世界坐标
```
调用方分两类：
- 地板/墙/窗/沙发/石板路：父节点在原点、且传的是世界坐标 → 世界==局部，**碰巧正确**
- 绿植（`Planter_A/B/C` 在 `(-1.62, 0.56, 2.04)` 等处）：传的是**相对 Planter 的局部偏移**
  → `SetParent(true)` 后再赋 `.position`，等于把局部偏移当世界坐标用，
  所有 Pot/Leaf 全被摆到**世界原点 (0, 0.4, 0)**，而狗在 `(0, 0.03, 0.35)`，直接压在狗身上。
  `Mat_Pet` 同理，垫子本体跑到原点。

修法：三个辅助函数统一改成局部坐标
```csharp
go.transform.SetParent(parent, false);
go.transform.localPosition = pos;
go.transform.localScale = size;
```
局部语义对上面第一类调用方也等价（父在原点），所以是安全收敛。

### 遮挡自检为什么漏报
旧 `VerifyNoOcclusion` 有两条过滤：
1. `if (r.bounds.center.z <= petPos.z + 0.05f) continue;`（只看狗身后）
2. 用「家具中心到相机→狗连线的水平距离」比阈值

跑到原点的叶片 z≈0，比狗的 z≈0.26 小 → 被规则 1 直接过滤掉了，
所以报「0 个遮挡」。改成**屏幕空间 AABB 重叠 + 深度比较**：
把包围盒 8 个角 `WorldToScreenPoint` 取外接矩形，
`rect.Overlaps(petRect)` 且 `r.bounds.center.z < petDepth` 才算遮挡。
这个判据不依赖任何坐标假设——玩家看到盖住就一定命中。

**教训：编辑器脚本里`SetParent(parent, true)` + `transform.position` 是陷阱，
父节点不在原点时会把局部偏移当世界坐标用。
层级辅助函数一律用 `localPosition`（配 `SetParent(parent, false)`），
写完立刻用 MCP dump 子物体的 `world`/`local` 复核，不要只看父节点位置。**
