## 七、运行时报错与修复记录

### 7.1 `DirectoryNotFoundException: ...\Assets\Animations\Dog\Dog_Idle.anim`

**根因**：`PetAnimationBuilder.EnsureFolder(parent, child)` 在 `parent` 不存在时，
递归建完父目录就`return` 了，从没创建最后一层。
所以 `EnsureFolder("Assets/Animations", "Dog")` 只建出了空的 `Assets/Animations`，
`File.Copy` 找不到目标目录。

**修法**：
1. `EnsureFolder` 递归补父目录后**不return**，继续建当前层
2. 新增 `EnsurePhysicalFolder()` —— `AssetDatabase.CreateFolder` 建的是Asset 管线目录，
   不保证磁盘已落盘，对磁盘写入前必须 `Directory.CreateDirectory`
3. `File.Copy` 换成 `AssetDatabase.CopyAsset`（走导入管线并生成 .meta）

### 7.2 `InvalidOperationException: You are trying to read Input using the UnityEngine.Input class`

**根因**：`Dog_001.prefab` **自带**资产商的demo 输入脚本，挂在内部的 `Dog_001` 物体上：

| 脚本 | GUID | 问题 |
| --- | --- | --- |
| `ithappy.Animals_FREE.MovePlayerInput` | `b2c67ce8...` | `Update()` 每帧调 `Input.GetAxis` / `GetKey` / `GetButton` |
| `ithappy.Animals_FREE.CreatureMover` | `be2f4aa7...` | `Update()` 每帧写 Animator 参数（`Vert` / `State`），会与 `AnimationOrchestrator` 抢同一个 Animator |

在 `activeInputHandler = 1` 下旧版 `Input` 调用每帧抛异常。
七个 prefab（Dog / Deer / Chicken / Kitty / Horse / Pinguin / Tiger）都带这两个组件。

**修法**：`PetSceneBuilder.RemoveAssetDemoComponents(instance)` 在实例化后销毁
`ithappy.Animals_FREE` 命名空间下的 `MovePlayerInput` / `CreatureMover` /
`PlayerCamera` / `ThirdPersonCamera`。**不改资产 prefab**，只在实例上剥离，
保证所有模型仍可正常复用。

**销毁顺序有硬约束**：第一版按 `GetComponentsInChildren` 的返回顺序销毁，结果报

```
Can't remove CreatureMover (Script) because MovePlayerInput (Script) depends on it
```

`MovePlayerInput` 声明了 `[RequireComponent(typeof(CreatureMover))]`，必须先销毁
**依赖方**再销毁**被依赖方**。`GetComponentsInChildren` 不保证依赖顺序，
所以改成显式的 `destroyOrder` 数组：

```
MovePlayerInput → ThirdPersonCamera → PlayerCamera → CreatureMover
```

销毁前先把所有待删组件 `enabled = false`，避免某个组件在 `OnDisable` / `OnDestroy`
里访问到已被销毁的兄弟组件。

另外 `CreatureMover` 的 `[RequireComponent(typeof(CharacterController))]` 会留下
`CharacterController`，它会跟 `PetController` 抢移动控制权（位移冲突），
由 `RemoveLeftoverRequiredComponents` 一并清除。

**诊断要点**：`Logs/Editor.log` 是累积的，grep 报错会拿到历史遗留。
应以「最后一个 `三个场景构建完成` 之后的片段」判断本次结果。

**诊断要点 2**：在场景文件里 grep 组件 GUID 搜不到 ≠ 已清理。
场景存的是 `PrefabInstance`（prefab 实例），组件随 prefab 进来，
必须看 `m_RemovedComponents:` 字段才能确认。

**修复后 Console 输出**：

```
[PetV1] 移除资产自带 demo 组件：ithappy.Animals_FREE.MovePlayerInput
[PetV1] 移除资产自带 demo 组件：ithappy.Animals_FREE.CreatureMover
[PetV1] 移除资产 RequireComponent 残留：CharacterController
[PetV1] PetController.obstacleMask = 256（层 8 = Walls），射线避障已启用
[PetV1] 三个场景构建完成：
```

最后一次构建之后 0 报错、0 异常。三个场景复查：残留资产脚本 = 无，
`CharacterController` = 无。

### 7.5 Unity fake null —— 写入场景的引用变空的根因

**这是本项目最难的一个坑，排查了八轮。**

现象：`WireOrchestrator` 的接线复核日志显示 `animationMap=OK`（内存里写进去了），
但保存后的场景文件里 `animationMap: {fileID: 0}`。

根因：`AssetDatabase` 的写操作（`CreateFolder` / `CreateAsset` / `SaveAssets`）
会触发资产重新导入，Unity 在这个过程中**销毁并重建 ScriptableObject 的 native 实例**。
C# 侧的引用还在（`is null` 为 false），但 Unity 重载的 `== null` 判断为 true —— 即 **fake null**。

致命之处：`map ?? fallback` **不会触发**，因为 `??` 只检查真 null。
结果就是把已死的对象写进场景，序列化成 `{fileID: 0}`。

**修复：把所有 AssetDatabase 写操作前置到场景接线之前**

```
1. EnsureFolder×2                <- AssetDatabase 写
2. BuildFloorMaterial()          <- CreateAsset
3. CreateInvisibleMaterial()     <- CreateAsset
4. PrepareWallsLayer()           <- SaveAssets（建 Walls 层）
   ↓ 下面不再有任何 AssetDatabase 写操作
5. 每个 Build*Scene 内部重新 LoadAnimationMap()
6. WireOrchestrator 写入引用
7. CreateWanderWalls(layerIdx)   <- 只创建 GameObject
8. ConfigureObstacleMask
9. SaveScene
```

`CreateWanderWalls` 已拆成 `PrepareWallsLayer()`（含 SaveAssets，前置）
与 `CreateWanderWalls(int)`（纯 GameObject，接线之后）。

**最终验证结果**

| --- | --- | --- | --- |

其他组件引用同样正常：

### 7.6 类名必须与文件名一致（Unity 硬性要求）

`MonoBehaviour` / `ScriptableObject` 的类必须单独放在同名文件里。
违反时 `ScriptableObject.CreateInstance<T>()` 返回 null，Console 报
`No script asset for XXX. Check that the definition is in a file of the same name`，
生成的 `.asset` 里 `m_Script: {fileID: 0}`。

本项目共 5 处违规，已全部拆为独立文件：
`PetPersonalityProfile`、`PetModelTestDemo`、`PetPerformanceProbe`、
`PetSceneInfo`、`PetRegionCollider`。

与 `AnimationOrchestrator` 冲突）。已在实例化时剥离。

`[RequireComponent(typeof(CreatureMover))]`，必须**先销毁依赖方**。

### 7.8 Walls Layer 已自动化

原先需要人工建层 + 配 mask，现已全部写进 `Pet V1 / 2. Build Scenes`：

| 函数 | 职责 |
| --- | --- |
| `EnsureLayerExists("Walls", 8)` | 通过 `SerializedObject` 改 `ProjectSettings/TagManager.asset`，在第 8 层（用户层起点）创建 `Walls`。已存在则复用 |
| `PrepareWallsLayer()` | 上一层的前置入口，必须在接线之前调用（含 `SaveAssets`） |
| `CreateWanderWalls(layerIdx)` | 四面墙建在该层，纯 GameObject 创建，接线之后调用 |
| `ConfigureObstacleMask(pet, layer)` | 把 `1 << layer` 写进 `PetController.obstacleMask`，同时设 `BodyHeight` |

顺带给 `SetPrivateField` 补了 `SerializedPropertyType.LayerMask` 分支
（Unity 6 里 LayerMask 底层存的是 `serializedVersion: 2` + `m_Bits`）。

**验证结果**

```
TagManager: layers[8] = Walls
PetPrototype / PerformanceTest: obstacleMask = m_Bits: 256（= 1 << 8）
Wall_North / South / East / West → layer 8
Floor → layer 0（不参与避障探测，不会被误判成障碍）
```

射线参数：`origin.y = BodyHeight(0.5) * probeHeight(0.25) + 0.1 = 0.225m`，
水平向前 `SphereCast(radius 0.08, dist 1.1)`，只测 `Walls` 层。

活动区 ±2.2m、墙体 ±3.0m（比活动区大 0.8m，让 `lookAheadDistance` 的一半能探测到，
否则避障形同虚设）。
