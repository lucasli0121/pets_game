# 微信小游戏试水打包清单（Unity 6000.6.4f1）

目标：用当前引擎版本跑通「WebGL 导出 → 小游戏转换 → 开发者工具 → 真机」，
以此判断 Unity 6 这条路是否可行。模型替换等这一步定了再做。

---

## 一、顺序判断：先微信，后模型

理由三条：

1. **风险性质不同。** 微信转换是门槛型风险（Unity 6 不在插件官方支持范围，可能根本走不通）；
   换模型是确定型工作（FBX + 材质 + 动画映射，一定能做，只花时间）。先验证可能否定整个方案的那一环。
2. **换引擎会作废模型工作。** 若 Unity 6 试不通需降 2022 LTS 或迁团结引擎，届时 FBX 导入设置、
   URP 材质、`PetAnimationMap` 动画绑定、3D 取景参数（`dogGroundLine` 那一套）全部要重来。
3. **买模型要花钱。** 钱应该花在链路验证通过之后。

### 但要拆成两段验证

免费模型（ithappy `Dog_001`）与付费边牧在面数、纹理尺寸、材质数、骨骼数上可能差一个量级。
所以：

- **段 A（现在）**：用免费模型验证链路能不能通。只看「能不能跑到真机首帧」，不看包体结论。
- **段 B（换模型后）**：重跑包体与内存验证。模型的成本才是真正的变量。

段 A 的结论不能直接套用到段 B。

## 三、上机前必须修的 3 项

### 1. Build Settings 场景挂错了（阻塞）

现状（`ProjectSettings/EditorBuildSettings.asset` 第 9 行）：

```
path: Assets/Scenes/SampleScene.unity
guid: 99c9720ab356a0642a771bea13969a05
```

应改为：`Assets/Scenes/PetPrototype/PetHome.unity`

**症状**：打出来是空场景，黑屏。第一反应会误判为「转换失败」，浪费排查时间。

### 2. `Exception Support` 不能设 None（阻塞）

工程里有 14 处 `catch` 做容错降级，分布在：

- `Data/PetJson.cs:222`
- `Data/PetSceneAssetCache.cs:241, 279, 289, 302`
- `Data/PetSceneConfigCache.cs:408, 432, 448, 466, 482`
- `Data/PetSession.cs:265, 354, 365`
- `Model/PetSceneLibrary.cs:143`
- `UI/PetDebugPanel.cs:245`

Unity WebGL 的 `Enable Exceptions = None` 下 try/catch 不生效，这些「读缓存失败就回退」「网络失败不崩」
的路径全部失效，表现为莫名其妙的静默失败。

**设 `Explicitly Thrown Exceptions Only`**。代价是 wasm 体积略增，可接受。

### 3. `Compression Format = Brotli`

小游戏 CDN 与包内资源都按 Brotli 处理，压缩率最高。

## 四、Player Settings 逐项

| 项 | 值 | 理由 |
|---|---|---|
| Scripting Backend | IL2CPP | WebGL 唯一选项 |
| Compression Format | Brotli | 体积最小 |
| Enable Exceptions | Explicitly Thrown Exceptions Only | 见上，不能用 None |
| Managed Stripping Level | Medium（先别 High） | 代码用手写 JSON 解析 + `[Serializable]`，High 有裁剪风险。跑通后再试 High |
| Development Build | 关 | 调试信息会显著撑大体积 |
| Data Caching | 开 | 二次加载走缓存 |
| Color Space | 保持现状 | 中途改会影响画面，另立议题 |
| Memory Size | 256MB 起 | 微信小游戏内存上限约 256MB |
| Auto Graphics API | 待验证 | 微信官方口径仅支持 WebGL 1.0。Unity 6 默认走 WebGL2，需确认能否降到 1.0 |

`Auto Graphics API` 这一条是本次试水最大的未知项。若 Unity 6 无法输出 WebGL1，
可能是直接否决 Unity 6 路线的理由。

## 六、四个闸门（按顺序过，不跳）

**闸门 1：WebGL 能否导出成功**
纯 Unity 侧，不碰微信。Build 成功即通过。失败说明 Unity 6 的 WebGL 本身有问题，直接换引擎。

**闸门 2：转换插件能否出 minigame/**
插件识别工程、转换无报错、生成 `minigame/` 目录。失败先查 AppID 与「快适配」授权，再查插件版本。

**闸门 3：开发者工具能否启动到首帧**
导入 `minigame/`，模拟器出画面。出不来先看 console 报错，重点查 wasm 挂载与资源路径。

**闸门 4：真机能否进场景**
预览二维码 → 手机扫码。这一关才暴露真实的性能与内存问题。

卡在 1 或 2：Unity 6 路线不通，换引擎，不要继续调。
卡在 3 或 4：大概率是配置或资源问题，可调。

## 七、已确认干净的部分

- 网络层全部 `UnityWebRequest`（`PetApiClient`、`PetSceneAssetCache`、`PetSceneConfigCache`），
  WebGL 原生支持，零改动。
- 无 `Thread` / `System.Net.Sockets` / `async Task` / `Task.Run`。单线程无障碍。
- `Assets/Resources` 仅 **825K**（10 张图标 + 5 张食物图 + 1 张肖像 + 1 个 asset）。
  首包 4MB 的压力不在资源侧，在 URP 的 wasm。
