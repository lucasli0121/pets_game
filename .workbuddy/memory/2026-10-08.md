### 项目基线（两份文档共同基准）
- Unity 6.6 + URP + C#，验证对象收敛为**一只 Border Collie**（购买资产，不自制模型）
- 分层：表现层 / 输入层 / 宠物核心 / 个性层 / 数据层 / 后端 / AI层 / 运营
- 后端：Python FastAPI + PostgreSQL(+Redis 可选) + S3 兼容对象存储
- V1 不做：多品种、照片/视频生成 3D、专属大模型、LLM 控帧、社交/排行榜、大量商城

### 架构硬约束（后续代码必须遵守）
- **所有输入（Touch/Voice/Feeding）先转 `InteractionEvent`，再由 `BehaviorController` 唯一决策**，严禁直接调 Animator
- 行为优先级 P0~P5：Growth/SceneCritical > Eating/Training > StrongInteraction > VoiceCommand > TouchReaction > AutonomousIdle
- **11 维 Personality**（0~1 长期性格向量）：energy/sociability/affection/curiosity/courage/impulsiveness/obedience/playfulness/independence/sensitivity/learningAbility
- **7 维 Emotion**（0~100 短期状态）：happiness/excitement/fear/anger/curiosity/sleepiness/hunger
- 注意坑：PetPersonality.energy（性格倾向）与 petStats.energy（当前精力）是**两个不同字段**，文档里已显式区分
- 所有 SaveData 带 `schemaVersion`，服务端用 `version` 做乐观锁
- 语音文本统一归一化成 Action Code（SIT/LIE_DOWN/STAND/COME/JUMP/PAW/SPIN/BARK），业务代码不判断中文字符串
- 10 种手势 Gesture ID；裂痕 VFX 走独立 UI 透明纹理，不做真实玻璃物理
- 扑屏链路：MULTI_SCRATCH → Excitement 累积 → Bark → Jump → Impact → Camera Shake + Screen Crack

### 里程碑
M1 3D生命体 → M2 触摸(5种) → M3 多指扑屏 → M4 行为核心 → M5 性格情绪 → M6 语音训练 → M7 喂养背包 → M8 成长 → M9 存档 → M10 真机优化

## 新增第三份文档：Animals FREE 模型验证需求方案（.md，24 章）

`docs/电子宠物 APP V1 — Animals FREE 模型验证需求方案.md`

### 它改了什么（相对前两份 docx）
1. **验证载体换人**：从「购买的 Border Collie 3D 资产」改为免费资源 **Animals FREE - Animated Low Poly 3D Models**。定位是「V1 Pet Behavior Prototype 的身体载体」，明确不是最终商业模型。
2. **范围大幅收窄**：只验证 Idle/Walk/Run + 触摸事件链路 + 自主行为。明确不做：高级动作(Sit/Lie/Jump/Bark/Eat/Sleep/Paw/Roll...)、BlinkShape/眨眼/眼动、CV 识别、LLM、云端(账号/云存档/PostgreSQL/Redis/对象存储)。
3. **排期改为三周**（Day1 建工程 → Day2 导模型 → Day3 Animator → Day4 PetController → Day5 Touch → Day6 Behavior → Day7 自主行为；第二周 Emotion/Personality/Debug UI/AnimationMap/Capability；第三周 屏幕互动/VFX/Sound/CameraShake/体验测试）。

### 本方案新增的技术契约（前两份没有或没细化）
- **PetCapability 枚举 + Fallback 机制**：行为系统不假设模型有能力；请求 Bark → 查 Capability → 无则 fallback 到 Excited→Run。枚举含 Idle/Walk/Run/Sit/Lie/Jump/Bark/Eat/Sleep/Attack。
- **AnimationOrchestrator + PetAnimationMap**：业务层只调 `PlayBehavior(PetBehavior.Walk)`，禁止 `animator.Play("Walk")`。换模型只改映射表。
- **PetState（最小版）**：Idle / Walking / Running / Interacting / Recovering（技术方案的 Eating/Training/Sleeping/Excited/Growing 留到后续）。
- **Behavior（最小版）**：Idle / Walk / Run / Stop / Look·Turn / Recover。
- **Emotion 最小版只有 3 维**：Happiness / Excitement / Sleepiness（0~100）。阈值口径：Touch → Happiness+2 / Excitement+1；MultiTouch → Excitement+5；久无互动 → Excitement 缓降。
- **Personality 11 维保留数据结构，但第一阶段只有 4 维真正参与计算**：Energy / Curiosity / Playfulness / Independence。
- **三个场景**：ModelTest / PetPrototype / PerformanceTest。
- **Debug Panel + 分级日志**（[Touch]/[Gesture]/[Behavior]/[Emotion]/[Animation]）。
- **最终输出物 18 项**，产物名 **电子宠物 APP V1 Prototype 0.1**。

### ⚠️ 待确认的契约分歧（新旧文档不一致，动手前需定稿）
1. **手势 ID 命名体系冲突**：技术方案用 `HEAD_TAP / NOSE_TAP / HEAD_STROKE / BACK_STROKE / HEAD_CIRCLE / FAST_SWEEP / MULTI_SCRATCH / MULTI_TAP / LONG_PRESS`（9~10 种，含身体区域语义）；新方案用 `HEAD_TAP / BODY_TAP / STROKE` + 屏幕级 `SCREEN_SCRATCH / SCREEN_TAP / SCREEN_SWIPE / SCREEN_MULTI_TOUCH`。**两套命名没对齐**，需定一份统一枚举。
2. **触摸区域识别**：技术方案要求 HEAD/NOSE/BACK/BODY 分区 Collider；新方案说当前模型可能没有分区 Collider，先只做整体 Pet Collider，之后再拆。
3. **行为优先级**：技术方案有 P0~P5 六级；新方案只列 6 种行为、未提优先级表。「不直接由业务代码操作 Animator」两边一致。
4. **验收标准重叠**：启动清单 (M1~M10) 与 新方案 (A~H 组) 是两套清单，里程碑颗粒度不同，需要合并成唯一一份。
