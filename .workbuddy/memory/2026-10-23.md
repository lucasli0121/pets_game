# 2026-10-23 第八轮：修 Toast 提示框不消失

## Bug

买了生日蛋糕后，「买到 生日蛋糕 ×1」提示框一直挂在屏幕中间，切到底导任何页面都不消失。
用户截图：商店「特殊」Tab + 生日蛋糕卡片 + 常驻灰底提示框。

## 根因

`PetUIRunner.Home` 写成了自动属性：

```csharp
public PetHomeUI Home { get; set; }   // 原代码
```

自动属性的 backing field `<Home>k__BackingField` 是编译器生成的私有字段，**Unity 不序列化它**。
`PetHomeSceneBuilder.cs:323` 那句 `runner.Home = home;` 只在编辑期有效，进 Play 反序列化后是 null：

```
Update() → Home?.Toast?.Tick()  →  整条 null 短路  →  ToastWidget.Tick() 永不被调用
→ _until = unscaledTime + 2f 的判据失效  →  提示框永久挂着
```

ToastWidget 本身没问题（`_toast` 在 `PetHomeUI.Start()` 里重建，所以提示弹得出来），
坏的只是「谁来调 Tick」。这也解释了为什么 `Tick()` 里专门用 unscaledTime 防 timeScale=0
的注释看起来白写了 —— 那层防护根本没被执行到。

同类问题在记忆里已有前科（`_pages` / `_tabButtons` / `_toast` 非序列化字段运行期全 null），
这次是**跨组件引用**也中招，之前的清单漏了这一类。

## 改了什么

1. `PetUIRunner.cs`：`Home` 改成 `[SerializeField] private PetHomeUI home;` + 属性包装，
   构建期的赋值现在能落进场景文件。
2. `PetHomeUI.cs`：新增 `BindRunner()`，在 `Start()` 最前面调用，
   `GetComponent<PetUIRunner>()`（没有就 AddComponent）后把 `Home` 指向自己。
   兜底场景文件是改代码前构建的、序列化字段还是空的情况。

两处都改是因为单改任一处都有漏：只改 SerializeField，旧场景文件里字段仍是 null；
只在 Start 绑定，则是每次都靠运行期补救、序列化里永远看不到这个引用。

## 验证

| 项 | 结果 |
|---|---|
| `runner.Home == ui` | True |
| 买生日蛋糕 | 积分 500→450，蛋糕 1→2，toast 弹出 |
| 2 秒后 toast | `toastActive=False`（frame 267，unscaledTime 44.75） |
| 连续再弹一次 | 先 True，5 秒后 False（frame 766） |
| Console | 0 error 0 warning |

## 流程

退出 Play → 重编译 → `PetHomeSceneBuilder.BuildHomeScene()` 重建场景（让 home 字段序列化进去）
→ 进 Play 验证。

# 第十轮：场景解锁接后台 + 场景图下载缓存 + 新用户赠送

## 1. 喂食（用户问的）——上一轮已接，本轮复核

`FoodPage.Feed` → `PetSession.Feed` → `POST /api/v1/pet/feed`。
实测：库存 1→0、exp 10→15，服务端 `exp=15 satiety=100 happiness=90` 一致。

## 2. scene/unlock + scene/use 接后台

- `PetApiClient` 加 `UnlockSceneRoutine` / `UseSceneRoutine`
- `PetSession` 加 `UnlockScene` / `UseScene`，成功后用 `balance` / `scenes` / `activeSceneId` 覆盖
- `ConfirmPopup.ConfirmUnlock` 走 session，解锁后接着调 `SwitchScene`
- `PetHomeUI.SwitchScene(sceneId, onDone)` 改成**先请求后切画面**：
  先切再发请求的话，失败时画面已经变了，玩家以为成功，下次进游戏又变回去
- `ScenePage.OnBadgeClick` 离线时拦掉解锁与切换
- `PetHomeUI.OnSessionChanged` 补一条：`stage.CurrentSceneId != State.activeScene` 就重贴。
  否则换设备登录后会出现「界面显示公园、画面还是小屋」

实测（UI 路径点按钮）：
`485 → 385`、`unlocked=[home_day, park_day]`、`state.activeScene=park_day`、
`stage.CurrentSceneId=park_day`；服务端 curl 一致。
重复解锁返回 `2202 场景已解锁`（后台文案准确，不是误报「积分不足」）。

## 3. 场景图从后台下载 + 本地缓存

**后台**：
- `config.Config` 加 `AssetDir`（默认 `assets`）
- 新增 `internal/api/asset.go`：`GET /assets/`，只放 `.jpg/.jpeg/.png/.webp`，
  挡 `..`，目录不存在/文件不在都 404 而不是启动失败，带 `Cache-Control: max-age=86400`
- 图片复制到 `pets_server/assets/scenes/`（+ `thumb/` 开发期用原图）
- 启动时 `ASSET_BASE_URL=http://127.0.0.1:8080/assets`

**客户端**：新增 `Data/PetSceneAssetCache.cs`
- 只处理 `sceneUrl` 以 `http://` / `https://` 开头的。**判据必须是协议前缀**：
  后台没配 `ASSET_BASE_URL` 时 `assetURL()` 返回的是相对路径（如 `scenes/xx.jpg`），
  按「非空」判断会拿相对路径发请求，报一个和配置毫无关系的网络错误
- 缓存文件名 `sceneId + "_" + FNV1a32(url) + ".jpg"`。
  不用 `string.GetHashCode()`：.NET 不保证跨进程稳定，拿它当文件名等于每次重启都换名字
- 先同步读缓存（不等网络），再异步补下载
- 下载用 `DownloadHandlerBuffer` 而不是 `UnityWebRequestTexture`：后者不给原始字节，没法落盘
- 解码前验 JPG/PNG 魔数：404 的 HTML 也会返回 200 字节，直接丢 `LoadImage` 只打一串底层报错
- **同一张图已加载过就跳过**：`EnsureAll` 一次启动会被调好几遍（Start + 每次配置变更），
  每遍都重新 `new Texture2D` 会白吃 8MB/张且旧纹理没人释放

**顺手修的两个连通性问题**：

1. **`PetSceneConfigCache` 没 token，自己拉必然 401**。日志会把人引到「后台挂了」。
   改成：没有 token 时静默不发请求；`PetSession` 登录后 `SetToken`，并把
   `config/get` 的**同一份原始响应**（新增 `PetApiResult.RawText`）喂给
   `TryApplyResponse`。一次请求两个消费者（food + scene）。
2. **`TryApplyResponse` 不触发 `ConfigApplied`**，导致「配置变了但相机没重摆、图没补」。
   事件移到 `TryApplyResponse` 内部抛（它有两个入口，放调用方会漏掉外部喂的那条）。

实测：
- 首次启动 `downloaded=3 failed=0`，背景 `home_day_remote 1080x1920`
- 缓存落盘 `home_day_99ce8fa1.jpg / home_night_c141a715.jpg / park_day_4025ca76.jpg`，
  字节数与原图一致（182424 / 289146 / 429711）
- 第二次启动 `hits=3 downloaded=0 failed=0`，背景名 `*_cache`
- `GET /assets/scenes/../../go.mod` → 404

# 第十一轮：签到状态查询接口（后台新增只读接口）

## 用户提的问题

「后台没有『查询今天是否已签』的只读接口」—— 上一轮做签到时发现的缺口。
这轮补上。

## 后台改动

`CheckInService.Status` 之前**存在但没有路由**，只随 `sync-state` 的
`checkin` 字段下发。这轮加了独立路由 + 补全字段。

| 改动 | 位置 |
|---|---|
| `domain.CheckInStatus` 加 `Date` / `CanClaim` | `internal/domain/model.go` |
| `CheckInService.Status` 填 `Date` / `CanClaim` | `internal/service/shop.go` |
| 新增 `CheckInService.StatusDetail`（多返回 balance / dailyLimit） | 同上 |
| 新增 `CheckInStatusResult` 结构 | 同上 |
| 新增 handler `checkinStatus` | `internal/api/client.go` |
| 路由 `POST /api/v1/checkin/status` | `internal/api/router.go` |
| 接口规格条目 | `internal/api/apidoc.go`（**漏了会被 apidoc_test 拦下**） |

### 响应结构

```json
{"claimedToday": false, "streak": 0, "reward": 100,
 "recentDates": [], "date": "2026-10-23",
 "canClaim": true, "balance": 500, "dailyLimit": 1}
```

### 三个新增字段的理由

- **`date`** —— 服务端认定的今天（UTC+8）。客户端算格子日期不再用设备时间：
  设备时间可被用户改，改到明天客户端就以为「今天没签」而多弹一次窗。
- **`canClaim`** —— 与 `claimedToday` **分开**。当前配置下两者等价
  （`daily_checkin` 有 `(user_id, date)` 唯一索引，一天一条），
  但后台把每日上限配成 >1 时两者会分开：今天签过了仍可能还能再领。
  客户端按钮文案以 `canClaim` 为准。
- **`balance` / `dailyLimit`** —— 查一次就能填满弹窗，不用再发一次 sync-state。

## 客户端改动

| 文件 | 改动 |
|---|---|
| `Data/PetApiClient.cs` | 加 `CheckInStatusRoutine` |
| `Model/PetRuntimeState.cs` | 加 `checkinCanClaim` / `checkinServerDate` 字段 + `OverwriteFrom` 补两行 |
| `Data/PetSession.cs` | 加 `RefreshCheckInStatus()`（只读查询）、`CheckinCanClaim` 属性；`ApplyCheckIn` 兼容 `canClaim`/`date`；`ClaimCheckInRoutine` 成功后置 `canClaim=false` |
| `UI/CheckInPopup.cs` | `Show()` 里先画本地态再 `RefreshFromServer()`；按钮文案改用 `canClaim`；格子日期优先用服务端 `date` |
| `UI/PetHomeUI.cs` | 自动弹窗的日期标记改用服务端 `checkinServerDate` |

**关键**：`ApplyCheckIn` 是 sync-state 与 checkin/status **两个来源共用**的，
字段结构一致，所以改一处两个入口都生效。

## 踩到的坑

**1. `Unity_RunCommand` 禁止 `System.Reflection.BindingFlags`**
想在脚本里反射取 `PetHomeUI._checkInPopup` 调 `Refresh()`，被拦
（`Script uses one or more unauthorized namespaces`）。
绕法：用 `ui.RefreshAll()` —— 它内部本来就会刷新已打开的签到弹窗
（`PetHomeUI.cs:769`）。

**2. 「画未签态」不能靠弹窗的 `Show()`**
`Show()` 会发网络请求，回来后状态被服务端覆盖。
正确顺序：改本地状态 → `SetActive(true)` → `RefreshAll()` → **立刻截图**。

**3. `daily_checkin` 唯一索引让「每日上限」实际上是 1**
`(user_id, date)` 唯一索引 ⇒ 一天一条记录 ⇒ `CheckinDailyLimit` 配多少都不影响。
`Claim` 里的上限分支是给「将来去掉唯一索引」留的。
`Status` 的 `canClaim` 与 `Claim` 保持同一口径，不要一个说能领一个说已签过。

## 遗留

- 签到入口图标仍是 `star`（现有图标集没有日历），等美术资源
- 自动弹窗的「一天只弹一次」用 PlayerPrefs 记服务端日期，
  换设备不会共享（这是有意的：每台设备各弹一次不算骚扰）
