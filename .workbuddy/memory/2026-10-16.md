## 2D vs 3D 决策：实测 3D 耦合度

用户判据：「如果 2D 更好开发、效率高、素材多容易实现，就改 2D；否则保持 3D」。

### 关键判断：2D 省的不是全部
- **不省的**：接下来 80% 的工作量（喂养 / 商店 / 成长 / 存档 / 12 个 UI 页面 / 语音）**跟 2D/3D 无关**，
  都在 UI 层 + 数据层，切换不会让它们变快。
- **省的**：① 小游戏首包体积（3D 实测已超：Skybox 单张 4.61MB、狗资产 2.4MB 未压缩）；
  ② 美术素材可得性（2D 素材包数量级更多，AI 生成 2D 可用、3D 不可用）；③ 目标机性能余量。
- **代价**：① 2D 动画素材要自己搞定（3D 的 idle/walk/run 是"白得"的骨骼动画）；
  ② **生命感上限取决于动画质量**——产品核心命题是「生命感」，2D 动画拼不好会比 3D 低模更僵硬。

### 结论与前置条件
按用户判据（2D 更易开发 / 素材多 / 好实现）→ **建议改为 2D**。但两条限定：
1. **只能在 Unity 内部改 2D，不能换引擎**。换 Cocos 等于 100% 重写 5037 行，成本从 35% 变 100%。
2. **先做动画观感验证（唯一 gate）**：拿一张 AI 生成狗立绘 → 手工拆部位 → 绑一个最简 idle（呼吸 + 摇尾）
   → Unity 2D 跑起来看观感。**观感能接受才改 2D；不行就是死路**，因为后续所有动画都走这条路。

**A. `Editor/PetSceneBuilder.cs`（模型假设最集中）**
