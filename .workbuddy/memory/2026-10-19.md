## 场景资源定位打通：远程优先 + 本地兜底（00:22）

用户问管理端「缩略图 / 场景资源 key」到底对应哪个文件。核查后确认是个**真实缺口**：
这两个字段只是原样存原样下发的字符串，`thumb_home_day`、`home_day` 在全工程找不到任何对应资源，
Unity 端 `Assets/Scenes/` 只有 PetPrototype 与 SampleScene。需求文档也只说「scene_key 对应 Unity 场景资源」，
没有定义解析规则 —— 即从键到文件的那一环从来没接上。

### 用户选型
1. 资源分发：**两者都要，远程优先、本地兜底**
2. 缩略图：**从大图裁切压缩**（不用生图工具，保证与实际场景一致）

### 实现
- `SceneItem` 拆成三列定位：`thumb` / `scene_path`（CDN 相对路径）+ `scene_key`（包内兜底）
- 新增环境变量 `ASSET_BASE_URL`，`ConfigService.ClientSnapshot()` 在副本上拼出
  `thumbUrl` / `sceneUrl` 两个只下发不入库的字段（`bson:"-"`）
- **留空时相对路径原样下发** —— 客户端据此判断「没有 CDN」，直接走 sceneKey
- `getConfig` 改用 ClientSnapshot；diff 仍用原始字段（URL 是服务端拼的，不该出现在变更对比里）
- 路径安全校验 `checkAssetPath`：拒绝 `http:` 开头的完整 URL、`..` 穿越、`/` 开头的绝对路径、反斜杠；
  且 `scene_path` 与 `scene_key` 不能同时为空
- 管理端场景页加「场景图路径」列，并写明 CDN 根地址不在这里配

### 缩略图产出
`art/scenes/thumb/` 三张 288×512（JPEG q82），17/20/30KB，由大图 LANCZOS 缩放得到。
源图在 `art/scenes/final/`，实际是 **1080×1920**（之前记忆里写的 864×1536 是旧版本）。

### 上传 CDN 的目录约定
保持 `scenes/` 与 `scenes/thumb/` 两级，与配置里的相对路径一一对应。

### 当前服务状态
8080 实例是带 `ASSET_BASE_URL=https://cdn.example.com/pets` 起的，**这是占位域名**，
换真实备案域名后改环境变量重启即可。

### 教训（编辑代码时踩到）
用 Edit 在函数签名行插入新函数时，old_string 只带了一行 `func sortLevels(...)`，
导致下面的 `for i := 1; ...` 循环头被连带删掉，编译才报错。
**插入代码时应把锚点范围取到最小且完整，宁可多带几行上下文**。

## 管理端接口文档页（01:35）

用户问「后台的接口文档地址是什么」——原先**没有在线文档**，接口清单只在 README 第 5 节。
用户选定方案：管理端内加一个接口文档页。

### 关键设计：规格放 Go 侧，不放前端
新增 `internal/api/apidoc.go`：`APISpec{Method,Path,Title,Group,Auth,Roles,Idem,Desc,Req,Resp,Example,Errs}`
+ `apiErrorCodes`（20 个）+ 6 条全局约定。经 `GET /api/admin/api-doc` 下发（鉴权，走 read 角色）。
理由：规格与路由注册同包，改路由时文档就在眼前；拼写错误编译期能查；不额外开口子。

### 把路由注册改成声明式（为了能自动比对）
`Routes()` 里所有 `mux.HandleFunc` 换成 `h.handle(mux, pattern, fn)`，自动累积到 `h.routes`。
- `RouteTable()` 挂在 **Handlers 实例**上，不是包级变量 —— 包级可变切片并发下是数据竞争。
- `app.App` 新增导出字段 `API *api.Handlers`，供测试读取路由表。
- `h.routes = h.routes[:0]` 允许重复调用 Routes()。

### 最重要的一点：用测试锁住「文档 ↔ 路由」契约
规格是**人写的声明**，不是反射生成的。加接口忘写文档，编译和运行都不会报错。
新增 `test/apidoc_test.go` 4 个用例做双向比对：
- 路由有、文档没有 → 失败；文档有、路由没有 → 失败
- 标了幂等却没声明 requestId → 失败
- 客户端路径不在 /api/v1/、管理端不在 /api/admin/ → 失败
**这个测试当场抓出了真问题**：文档接口 `GET /api/admin/api-doc` 自己漏写了，
写完第一条后立刻失败，补上才通过。这正是加测试的价值。

### 管理端页面
`#apidoc` 页：左侧 31 条接口清单（方法色块 + 路径），右侧详情（标签/请求字段表/响应字段表/错误码）

## A8 用户资料：活跃度统计 + 喂养记录（01:40）

用户要求用户查询增加：平均每天登录次数、总登录次数、最大在线时长、平均每天喂养次数、
平均每天花费积分，以及用户喂养记录（喂养时间 / 食物名称 / 花费积分）。

### 三个口径问题先问了用户（不要自己定，数字大小直接受影响）
1. **喂养花费积分**：积分实际在「买食物」时扣，喂食只扣库存，「喂一次花了多少」严格说不存在。
   选**按食物当前单价估算**（不选库存批次 FIFO，V1 不值得）。
2. **在线时长**：客户端没上报心跳。选**登录间隔近似**（相邻两次登录时间差，单次封顶 2 小时），
   不选心跳接口（V1 客户端还没写）。
3. **日均分母**：选**活跃天数**（daily_active 条数），不选「注册至今天数」。

### 实现
新增 `internal/service/session.go`：
- `Session()` 登录时调用：login_count +1、active_days 首登 +1、结算上次会话时长
- `StatsOf()` 汇总；`ActiveDaysOf()` 以 daily_active 为准
- `FeedRecords()` 从 action_log 取 feed 记录，补食物中文名与当前单价
- users 新增字段：login_count / active_days / total_online_ms / max_online_ms / last_session_end
- **在线时长用两条 update**（`$inc` total + `$max` max 分开），不混在一个 update 里

**去重**：`Login` 里原本自己 `$set last_login_at`，与 Session 重复。改成 Session 统一维护，
Login 的 default 分支只更新 nickname/avatar/unionid（且 len(set)>0 才发请求）。

**列表页性能**：SearchUsers 原本逐用户查（每用户 2 次 count），加统计会变 N+1。
改成 `aggregateBriefStats()` 对整页做 **3 次聚合 + 1 次投影查询**，查询数不随页大小线性增长。

管理端：列表加 5 列（活跃天/登录总日均/最长在线/日均喂养/日均花费）；
详情加「活跃与使用」6 张卡 + 喂养记录表 + 两行口径说明（statsBasis / statsCaveat 由服务端下发，
前端直接展示，避免运营把估算值当精确值）。

### 顺带抓出接口文档的两个真错误（重要教训）
真机联调时领养报 `unknown field "curious"`。查出来 `domain.Personality` 实际字段是
**curiosity / affection / independence**，而我上一轮写的接口文档写成了
**curious / affectionate / independent** —— 三个字段名全错。
这类错误 Go 编译发现不了（都在字符串里），测试也发现不了（测试用的真实结构，从没错过）。

**补了 2 条测试**（`test/apidoc_test.go`）：
- `TestDocs_示例是合法JSON`：POST 示例必须能反序列化（GET 是 query string，跳过）
- `TestDocs_示例字段名对得上真实结构`：用 `DisallowUnknownFields`（与服务端 decode 同行为）
  反序列化示例里的 personality，字段名对不上直接失败
写完当场又抓到 `independent` 也是错的 → 改成 `independence` 后才通过。

### 统计测试（7 个，全在 test/userstats_test.go）
- 同一天登录 3 次 → loginCount=3 但 activeDays=1（不能按登录次数刷活跃天数）
- 间隔 30 分钟 → 累计/最长都 30 分钟
- 间隔 10 小时 → 封顶 120 分钟
- **两次会话 60 分 + 10 分 → 最长仍 60、累计 70**（专盯 `$max` 是否生效，这是最易写错处）
- 买 2 次牛肉罐头喂 2 次 → 喂养 2 次、花费 20 分
- 零值用户不出现 NaN
- 管理端列表与详情的字段名逐个断言

28 用例全绿（15 验收 + 4 文档 + 2 示例校验 + 7 统计），20.5s。
