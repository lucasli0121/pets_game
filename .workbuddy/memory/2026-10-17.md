# 2026-10-17

## 三端（Windows / Android / 微信小游戏）虚拟支付可行性核查

用户问：V1 要出 3 个平台，虚拟支付买金币能否三端都实现。

### 结论
技术上三端都能做，但**是三套完全不同的支付通道 + 三套资质 + 三种抽成**，不是一套代码跑三端。
Unity 不提供跨平台支付能力，这层必须自己抽象 + 分别实现。

### 通道与抽成对照
| | Windows 桌面 | Android | 微信小游戏 |
| --- | --- | --- | --- |
| 通道 | 无内建。Steam→Steam Wallet；自建→微信支付/支付宝 | 国内商店→华为/小米/OPPO/vivo/应用宝各自 IAP；自发→微信支付/支付宝 | `wx.requestVirtualPayment`（小游戏虚拟支付） |
| 抽成 | Steam 30%；自建仅支付通道费 | 国内渠道 30%–50% | 安卓开发者基础约 70%；iOS 2026 起接入苹果 IAP，微信抽 15%（另有报道称开发者可达 85%，两口径不一致，以官方后台为准） |
| 前置资质 | Steam 国际版不需中国版号；国内平台/自建需版号 | **版号 + ICP 许可证 + 文网文 + 各渠道开发者账号** | **企业主体 + 版号** |
| 用户体系 | 自建 | 自建 | 微信 openid（免登录） |
| 结算 | Steam 月结 | 各渠道月结 | iOS 结算 45–60 天 |

- 微信虚拟支付 2026-04-01 起要求**全终端（iOS/安卓/Windows/鸿蒙）都走虚拟支付通道**，禁止普通支付或外链跳转。
- iOS 苹果支付是**独立开关**，默认关闭；**iOS 不支持沙箱**，只能现网测。
- **代币兑换比例一旦发布不可修改**，上线前必须定死。
- 小游戏 IAA 政策 2026：30 天最高 90% 分成，90 天最高 85%。

### 版号：多端可以共用一个，但要「增报」
- 2021 年的规则是「同一游戏不同平台需分别申请版号」——《哈利波特：魔法觉醒》只有移动版号，PC 版被判无证运营下架。
- **2022-09-13 起**允许在**原版号不变**的前提下**增报客户端 / 主机 / 页游版本** → 一个版号可覆盖多平台。
- 数据：多端版号 2023 年 77 款、2024 年 110 款、2025 年 139 款（131 双端 + 8 三端）。
- → 本项目 Android + 微信小游戏都属移动端，**PC 是客户端，需要增报或单独申请**。
- **待确认**：移动版号增报客户端后，能否同时覆盖「微信小游戏版」——须向出版单位确认，不能按「一个版号全包」规划。

### 给用户的建议（已给）
1. **Windows 版先当开发/测试载体**：Unity 切 Build Target 即可出 exe，几乎零成本；
   正好弥补「没有 Mac 不能跑 iOS 真机」的空缺。**V1 阶段不做真实支付。**
2. 支付优先只在小游戏做（抽成最低、资质最轻、openid 免登录、结算最规范）。
3. Android 支付等版号下来再做；国内商店要聚合方案，否则要接 5 套 SDK。
4. 架构上先留 `IPaymentProvider` 接口（Purchase(skuId) → 回调），V1 用 Fake/沙箱实现。
5. **订单签名与价格校验必须放后端**，前端价格不可信；金币到账要「先校验后发放 + 幂等」，
   与 PRD「购买先校验后提交、幂等」的约束一致。

## PC 版国内上架是否必须走 Steam（核查）

**结论：不需要走 Steam。Steam 只是境外渠道之一，而且它是唯一不需要中国版号的规模化 PC 渠道。**

### 国内 PC 渠道与版号要求（有官方出处）
| 渠道 | 版号 | 出处 |
| --- | --- | --- |
| **WeGame（腾讯）** | **必须** | WeGame 开发者平台 FAQ 原文：「中国大陆地区的游戏登陆 WeGame 之前需要在版署获得版号」 |
| **蒸汽平台（Steam 中国 / 完美世界运营）** | **必须** | 只上架过审游戏；2026 年在架约 **536 款**，而全球 Steam 2025 年新上架 19000+ 款 |
| 方块游戏 / B站游戏中心 / TapTap PC / 4399 | 必须 | 行业通例 |
| 官网自建下载（exe） | **必须**（无版号属「非法出版」）+ 网站 ICP 备案；收钱还需 ICP 许可证 | — |
| **Steam 国际版** | **不强制** | 运营主体在境外；但属灰色地带，美元结算，抽成 30% |

→ **国内没有任何一个正规 PC 渠道能绕开版号。**

### 对本项目的结论
1. **V1 阶段 PC = 内部测试载具，不对外、不碰渠道，零成本。**（也正好补上「没 Mac 跑不了 iOS 真机」的空缺）
2. 若将来要在国内发售 PC 版：**版号申报时就把「客户端」一起增报**。
   参考反面案例：《哈利波特：魔法觉醒》只有移动版号，PC 版被判无证运营下架。事后补报比一开始就增报贵得多。
3. 想快速拿海外 PC 用户 → Steam 国际版（不要版号），但注意国内合规灰色地带。
4. 配套事实：**WeGame SDK 支持 C++ 和 C#**，Unity 接 WeGame 不需要换技术栈。

### 补充：版号通用门槛（无论哪个平台）
出版单位须持《网络出版服务许可证》→ 版号以其名义申报；须提交完整包体（不能 DEMO 申报）；
**必须接入国家实名认证 + 防沉迷（830 新规）**；研发/发行须为企业法人；
出版服务费市场价约 5 万–20 万。

## 版号申请流程（已调研，产出文档）

**用户答复「好的」= 接受三端分发/资质清单 md 的提议 → 已创建**

### 官方受理条件（上海一网通办《出版国产网络游戏作品审批》原文，硬条件）
1. 出版单位须为具有网络游戏出版范围的**网络出版服务单位**
2. 作品已办**著作权登记**（或公证 / 著作权人自我声明承诺）
3. 著作权人须为**中国公民或内资企业**
4. **游戏运营机构须具有 ICP 许可证**
5. 符合《出版管理条例》《互联网信息服务管理办法》《网络出版服务管理规定》
6. 运营须符合未成年人保护规定
- 审批**不收费**；结果为国家新闻出版署 ISBN 号 + 核发单，**有效期无限期**
- 法定时限：受理 5 + 审查 10 + 决定 10 + 颁证送达 10 工作日（不含专家评审与公示）

### 实际周期（2026 白皮书口径）
前期准备 1–3 个月（资质 + 内容自检）→ 材料 2–4 周 → 出版单位初审 15–20 工作日 →
省级（形式 5 + 实质 20–30 工作日）→ 国家终审 40–60 工作日 → **合计 3–6 个月**
- 审核意见反馈时限统一 10 个工作日
- **北京/上海等试点区申报可缩短约 30%**
- **休闲益智 / 教育科普类可缩短约 20%**
- 申报门槛：**开发进度不低于 75%**，不能 DEMO 申报

### 材料三大类
A 基础资质：营业执照、**ICP 许可证**、软著（盖章）、出版合同、合规承诺书
B 游戏内容：说明书（含**付费规则**）、完整脚本、**10 分钟以上演示视频**、完整包体、**区分成年/未成年的测试包与账号**
C 辅助：防沉迷说明 + 测试报告、屏蔽词库、服务器所在地证明、截图

### 品类数据（2025 年过审）
休闲益智占比 **44.7%**；模拟经营 + 儿童教育合计 31.2%；大厂仅占 15.3% → 中小团队有空间。
本项目建议争取按「移动-休闲益智」申报（可吃 20% 周期缩短），但"电子宠物养成"是否被判模拟经营须与出版单位确认。

诱导未成年人消费；付费规则缺失；无版号先上线（非法出版，下架 + 罚款）。

## IAA（纯广告变现）是否免版号（核查，2026-10-17）

### 结论：分平台，差别极大
| 场景 | 微信小游戏 | 抖音小游戏 | **原生 APP（安卓/iOS）** |
| --- | --- | --- | --- |
| 纯 IAA（无任何充值/道具付费） | 版号 **⚠️ 平台准入可豁免** | ⚠️ 可豁免 | **✅ 强制，无豁免** |
| IAP 内购 | 版号 **✅ 强制不可豁免** | ✅ 强制 | ✅ 强制 |
| ICP 许可证（纯 IAA） | ❌ 平台托管豁免 | ❌ | **✅ 强制** |
| 文网文 | ❌ 非强制 | ❌ | ❌ 非强制 |

来源：2026 广州游戏合规《小游戏和手游资质差异》对比表（微信/抖音小游戏、原生 APP 三类对照）

### ⚠️ 三条必须讲清的边界
1. **「平台准入豁免」≠「法律豁免」**
   - 法规口径：《网络出版服务管理规定》第二十七条，网络游戏上网出版前必须审批。
     有合规服务商明确表述「无论是否收费、无论内购还是广告，都属正式运营，必须版号」。
   - 平台口径：微信在实际准入时对纯 IAA、无内购的休闲品类放行。
   - → **能上，但踩在平台口径上而非法条上，政策随时可能收紧。** 该对比表自己标注：「仅代表上架平台准入要求，不代表完全规避监管长期风险」。
2. **「无版号品类」的范围由微信界定，且会调整。** 玩法超出范围时，即使无内购也可能被要求补版号。
3. **Android APP 即使纯 IAA 也强制版号 + ICP 许可证，无豁免。** → **免版号只对小游戏成立，对独立 APP 不成立。**

### 对本项目的判断：算不算「纯 IAA」
PRD 现状：初始金币 500、商店（食品/道具/特殊）、场景解锁 100/200/300 金币。
- 若金币**只能靠看激励视频获得**、商品只能用金币买 → 属纯 IAA，可走免版号
- 只要有任一指向内购：金币可充值 / 付费解锁 / **抽奖开箱** → 立即变 IAP，版号强制
- **红线：不要做抽奖/开箱付费机制**，那是监管重点核查项

### 建议策略：两条线并行
- **IAA 版本先上线**（13–37 工作日，走免版号），最快拿到真实用户验证
- **版号同期申请**（4–6 个月），下来后企业主体可在后台开通虚拟支付，升级为 IAP
  （企业主体可直接升级；个人主体不行，必须重新注册）
- 代价：IAA 的 ARPU 远低于内购；微信 IAA 分成 30 天最高 90%、90 天最高 85%；
  开流量主门槛 UV ≥ 1000；且「金币经济」要重设（只能靠看广告产出）

### ⚠️ 必须同步改的产品设计（否则会被判成内购）
1. 金币降级为「游戏内积分」，全站不得出现「充值」「购买」「元」「¥」
2. **金币唯一产出 = 看激励视频**——PRD 里「金币来源待确认」这个缺口必须补（现有设计只有花币没有赚币，纯 IAA 下闭环不成立）
3. 移除任何充值入口，包括灰掉的按钮（审核会看）
4. **不做抽奖 / 开箱 / 概率付费**（监管红线）
5. 商店只卖金币能买的东西，不得有付费礼包
6. 场景解锁（100/200/300 金币）可保留，因为金币非付费获得

Windows 仍可出 exe 做内部测试与真机验收（不对外、不收款，不涉资质）。

## 多平台「一起上」成本核查（22:22）

用户设想：V1 目标平台 = 微信小游戏 + 抖音小游戏 + TapTap 小游戏（若有）+ 海外 Steam，认为这样成本最低。

### 结论：方向对，但「成本最低」判断错了
**总成本 = 平台数量 × 每平台边际成本。最低成本 = 平台数量最少，不是最多。**

### 各平台增量成本与无版号可行性（已核实）
| 平台 | 增量成本 | 无版号能否正式上线 |
| --- | --- | --- |
| 微信小游戏（首个） | 最高（首包裁剪 + CDN + WebGL 兼容，一次性） | ✅ 纯 IAA 可（13–37 工作日） |
| 抖音小游戏 | 中（换抖音 SDK、重做包体、另一套审核） | ✅ 纯 IAA 可（多源一致）；公司主体才能开流量主 |
| **TapTap** | 中 | **❌ 无版号只能「开放试玩」，不能正式上线** |
| **Steam** | **高，且性质不同** | 不需版号，但 **IAA 模式不成立** |

### TapTap 的硬事实（官方开发者文档，证据确凿）
TapTap 资质表原文：
- 联网 + 有内购 → 版号 + 软著 + ICP备案 + 防沉迷 + 隐私 → **「正式上线」**
- **联网 + 无内购 → 只有 ICP 备案 + 防沉迷 + 隐私 → 只能「开放试玩」**
- 原文：「『正式上线』开放下载或开放内购，**必须提供版号**；若厂商没有提供版号，**只能以『开放试玩』形式上架**」
→ **TapTap 不是「零成本搭便车」，无版号拿不到正式分发，价值有限。等版号再说。**

### 抖音的注意点
- 纯 IAA 免版号：多源一致
- 但抖音要 **ICP 核准**（不是微信那种「小程序备案」），是另一套材料
- **⚠️ 口径冲突**：有来源称「一旦涉及广告激励，备案就必须前置，轻度无版号仅限单机、无付费、无实名体验型」——
  与「纯 IAA 免版号」矛盾。**须向抖音开放平台确认。**
- 抖音 IAP 要求：版号 + ICP 证 + 软著

### Steam 为什么不能算进 V1
- Steam 没有广告联盟，玩家普遍拒斥广告 → **IAA 模式在 Steam 不成立**
- 要么买断制，要么 Steam Wallet 内购（30% 抽成）
- 还需要：英文（国际化）、Steamworks 集成、Steam Direct 100 美元/款、PC 优化
- → 它要求的是**另一种产品形态**，不是「同一套包顺手多传一个渠道」

### 建议的分期
1. **V1 只上微信小游戏**：一个平台足够验证「生命感 + 留存」，也能攒到开流量主所需的 UV ≥ 1000。多平台会拖慢上线。
2. **阶段二加抖音**：同类小游戏，边际成本最低；抖音用户画像与微信差异大，值得单做。
3. **TapTap 等版号**：无版号只能试玩页。
4. **Steam 不进 V1**：需要独立的商业化设计与英文版本。

## IAA 广告接入方式（核查，官方文档）

### 不需要自己找广告商
用微信官方广告联盟（腾讯广告），通过开通 **「流量主」** 变现。广告主由平台匹配，开发者只管放广告位。

### 流量主开通条件（ad.weixin.qq.com/docs/237 官方原文，满足任一）
1. 小程序**累计独立访客 UV > 500** + 无刷粉行为 + 未曾严重违规记录
2. 开通内置游戏圈产生有效活跃（用户从小游戏进游戏圈产生消费/转评赞）+ 发布官方帖 5 篇
3. 同公司主体名下已有小程序：已开通流量主 + 从昨日开始持续 1 个季度有变现 + 无流量主违规记录

> ⚠️ 部分第三方文章写「UV ≥ 1000」，**官方文档是 > 500**，以官方为准。（1000 是微信「小程序非游戏类目」代运营的门槛，不是小游戏的）

### 接入四步
1. **开流量主**：微信公众平台 → 推广 → 流量主 → 申请开通 → 同意协议 → 选广告位
2. **建广告位**：流量主 → 广告管理 → 新建广告位 → 选「激励视频」→ 得到 `adunit-xxxx`；
   时长可选 15 秒 / 30 秒；**广告位需审核 1–3 工作日，要提前建，别等游戏过审**
3. **写代码**（Unity 经 WXSDK 转换后用 `WeChatWASM`）：
   `WXBase.CreateRewardedVideoAd(new WXRewardedVideoAdParam { adUnitId = "adunit-xxx" })`
   → 监听 `OnLoad`（预加载就绪）/ `OnClose`（判断 `res.IsEnded` 完整观看才发奖励）
4. **结算**：按月自动结算；**必须及时补财务资料（对公账户/发票），否则影响打款**

### 必须注意的点
- **UV 500 是上线后的门槛** → 存在「鸡生蛋」：上线初期没广告，金币得靠别的产出（签到 / 互动任务）
- **广告加载失败 / 无填充必须有降级**，不能卡住用户流程
- 激励视频必须**用户主动触发**、**看完才发奖励**；关闭按钮清晰；禁止诱导点击
- 奖励发放要做**服务端校验 + 冷却**，防重复领取
- **eCPM 波动大，不要按固定数字做收入预测**，开流量主后看真实数据再定

### 设计影响
金币产出路径需分两段：
- 上线期（未开流量主）：签到 / 互动任务产出金币
- 开流量主后：主路径切为「看激励视频得金币」，签到保留兜底
