# 电子宠物 APP V1 需求文档

版本 V1 · 依据《V1 UI 原型图》展板整理 · 标【待确认】的条目是审查中发现的缺口，需要你们决定

## 1. 项目概述

- 项目名称：电子宠物 APP（V1）【待确认：正式名称】
- 版本目标：验证核心玩法和用户体验，控制开发成本
- 核心亮点：3D 宠物互动、食品喂养、场景切换、宠物成长
- 目标用户：18–35 岁，喜欢宠物、休闲娱乐的用户
- 平台：iOS / Android，Unity 6.6【待确认：是否为 LTS 或稳定版本】
- 设计风格：温暖、极简、玩具感、沉浸（3D 场景加动态交互）

## 2. V1 范围

范围内：宠物选择（仅 Border Collie）、3D 主场景、食品背包与喂食、商店（虚拟金币）、3–4 个场景、成长与性格查看、6 个语音指令训练、基础设置。

范围外：真实支付、社交、云存档、多宠物、照片换肤与习性学习、AR、宠物装扮。

## 3. 功能需求

### 3.1 宠物选择

- 展示可选宠物卡片，含名称和性格标签（温顺·聪明·好奇）。
- V1 仅开放 Border Collie，其余显示“更多宠物即将开放”。
- 选择后进入主场景，选择结果本地保存。

### 3.2 主场景（首页）

- 3D 场景中显示宠物；顶部显示等级和亲密度，右上角为设置入口。
- 宠物会主动提示（如“来摸摸我呀\~”），用户可触摸互动。【待确认：支持哪些手势，见第 10 节】
- 快捷入口：食物、训练。底部导航：宠物、食品、商店、场景。

### 3.3 食品系统

- 背包按全部 / 主食 / 零食 / 特殊分类，显示数量和效果。
- 食品详情显示效果和当前拥有数量，点“立即喂食”开始喂食。
- 喂食后扣减库存，宠物状态和成长经验更新。

展板中的食品：

| 食品 | 效果 | 价格（金币） |
| --- | --- | --- |
| 牛肉狗粮 | 饱腹 +10，成长经验 +5 | 10 |
| 狗狗饼干 | 快乐 +8 | 15 |
| 鸡肉干 | 亲密 +10 | 20 |
| 生日蛋糕 | 快乐 +20，亲密 +15 | 50 |

### 3.4 商店

- 用金币购买，分食品 / 道具 / 特殊三类；购买前确认，成功后扣币并放入背包。
- 展板示意初始金币为 500。【待确认：金币来源、道具具体内容】

### 3.5 场景

- 3–4 个场景：家中（默认）、公园、海边、夜晚；其余用金币解锁（海边 200，夜晚 300，公园价格展板未清晰标注）。
- 不同场景下宠物行为不同：家中休息、玩玩具；花园 / 公园探索、奔跑、玩耍、互动；夜晚安静、休息。
- 【待确认：场景名称，展板第 7 页是海边，第 11 页是花园】

### 3.6 成长

- 等级与经验进度；四项状态：亲密度、饱腹度、快乐度、精力。
- 成长经验来自喂食等互动。【待确认：升级经验曲线、状态随时间衰减和离线结算规则】

### 3.7 性格

- 五项数值：活泼、好奇、亲人、独立、学习。V1 仅查看，后续支持培养。

### 3.8 训练（语音）

- 点击麦克风说出指令，识别后宠物执行动作；V1 共 6 个指令：坐下、过来、卧下、握手、跳跃、转圈。
- 界面显示已学会 / 未学会状态。【待确认：指令如何“学会”、识别失败时宠物的表现】

### 3.9 设置

- 账号管理、通知设置、音效设置、语言设置（展板为简体中文）、关于我们。

## 4. 核心流程：喂食

1. 点击食品，打开食品详情。
2. 点击“立即喂食”，关闭 UI。
3. 食品出现在 3D 场景中。
4. 宠物注意到食品，闻，走近，吃。
5. 吃完后宠物表现满足，状态更新。

## 5. 数据字典

展板中的核心字段：

- 用户：userId、nickname、createdAt
- 宠物：petId、name、level、exp、personality（json）、capability（json）
- 道具 / 食品：itemId、type、effect、price、icon

建议补充（界面已用到，但展板数据字典没有）：

- 用户：金币余额、语言设置
- 宠物：亲密度、饱腹度、快乐度、精力、上次更新时间、已学会的指令
- 背包：itemId 与数量
- 场景：sceneId、价格、是否已解锁

## 6. 技术方案

- 三层结构：UI 层（组件、页面交互、本地缓存）；C# 游戏逻辑层（宠物状态、物品系统、场景管理、数据管理）；Unity 3D 层（模型、动画、物理、音效、特效）。
- 关键技术：Unity 6.6 + URP、C#、ScriptableObject（配置数据）、Addressables（资源管理、后续扩展）、本地存档。
- 后台（V1 可选）：无后台，本地存档；后续可扩展云存档、社交和数据分析。
- 建议补充：Input System 做触摸手势；端侧语音识别加口令匹配；Unity Localization 做多语言；存档用加密 JSON 文件，不建议用 PlayerPrefs 存金币和背包。

## 7. 非功能需求

- 流畅度：展板要求移动端 60 FPS。【建议：主流机型稳定 30 FPS 以上，高端机 60 FPS】
- 包体：500 MB 以内；系统：Android 8.0+ / iOS 13+（需与所选 Unity 版本核对）。
- 3D 模型优化：LOD、动画压缩。

## 8. 验收标准

- 完成宠物选择并进入主场景。
- 完成喂食流程，含动画和状态变化。
- 完成场景切换，并能看到宠物行为变化。
- 完成商店购买，并正确扣除金币。
- 完成 6 个语音指令训练。
- 在主流机型上运行流畅，无明显卡顿。
- 【建议补充】首次使用麦克风有权限说明，拒绝权限时有降级方案。

## 9. V2 及以后

更多宠物（如德牧、柯基）、多宠物养成与互动、真实支付（Apple IAP / Google Play / 国内支付）、社交（好友、宠物拜访）、云存档与跨平台、AI 个性化行为、更多场景与环境互动、宠物装扮与家具、AR 模式。

## 10. 待确认事项

**优先级高（影响范围和预算）**

1. 触摸互动：展板有“来摸摸我呀”的提示，但需求和验收里没有手势。前期讨论的摸头、绕圈、多指挠屏、吠叫、冲撞裂屏，是进 V1 还是放 V2？
2. 宠物范围：V1 只有 Border Collie，前期计划是狗加猫、多品种。请确认 V1 是否不含猫和其他狗。
3. 美术风格：展板是写实渲染，低预算可买到的多是卡通低模资源，成品会有落差。请确认 V1 以哪种风格为准。
4. 金币闭环：只有花币，没有赚币。需定义金币来源（训练、互动、签到等），否则用户很快花光。
5. 场景数量与名称：统一为哪几个场景；每个场景都是一套环境美术，建议 V1 先做 2 到 3 个。

**优先级中**

6. 数据字典补全（见第 5 节）。
7. 存档与账号：无后台时“账号管理”要定义成什么；本地存档的防丢失和防篡改程度。
8. 语音识别：技术方案里没有，需确定端侧还是云端，以及隐私政策和权限说明。
9. 本地化：展板只有简体中文，语言设置要支持哪些语言；界面中的 Border Collie 需要本地化名称。
10. 状态规则：状态随时间衰减、离线结算、喂食次数上限。
11. 成长阶段：只有等级，没有幼犬到成年的外观变化，需确认 V1 是否包含。
12. Unity 版本：确认 6.6 是否稳定，正式项目建议使用 LTS。
